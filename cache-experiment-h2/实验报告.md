# H2 直查 vs Redis 缓存 性能对比实验

## 实验目的

对比 H2 内存数据库直查与 Redis 缓存两种方式在不同查询场景下的响应时间差异，验证引入缓存对读取性能的提升效果。

## 实验环境

| 组件 | 版本/配置 |
|------|-----------|
| JDK | 17 |
| Spring Boot | 3.2.5 |
| H2 Database | 2.2.224（内存模式） |
| Redis | 6.x（Docker） |
| MyBatis-Plus | 3.5.6 |

### 数据规模

- `t_user` 表：10,000 条记录
- `t_order` 表：约 27,000 条记录（90% 用户有 3-5 条订单，20% 用户额外有 1 条订单）

## 环境准备

```bash
# 1. 启动 Redis
cd cache-experiment-h2/docs/docker
docker compose up -d

# 2. 编译项目
mvn clean compile -pl cache-experiment-h2

# 3. 启动应用
mvn spring-boot:run -pl cache-experiment-h2
```

## 实验步骤

使用 ab 压测对比两种模式：`/api/direct/**`（直查 DB）vs `/api/cache/**`（缓存命中）。

```bash
# 单表查询
ab -n 10000 -c 1000 http://localhost:8080/api/direct/users/1
ab -n 10000 -c 1000 http://localhost:8080/api/cache/users/1

# 连接查询
ab -n 10000 -c 1000 http://localhost:8080/api/direct/users/1/orders
ab -n 10000 -c 1000 http://localhost:8080/api/cache/users/1/orders
```

## 预期结果

| 对比项 | 预期结论 |
|--------|----------|
| 直查 vs 缓存未命中 | 缓存未命中略慢于直查（多了 Redis 写入开销） |
| 直查 vs 缓存命中 | 缓存命中显著快于直查（跳过 DB 查询） |

## 实际测试数据

### 场景1：单表查询

#### 压测数据（ab -n 10000 -c 1000）

| 指标 | 直查 DB | 缓存命中 |
|------|---------|---------|
| QPS  | 8110.24 | 10175.79 |
| 平均耗时 (ms) | 123.301 | 98.272 |
| P99 耗时 (ms) | 244 | 165 |

### 场景2：连接查询

#### 压测数据（ab -n 10000 -c 1000）

| 指标 | 直查 DB | 缓存命中 |
|------|---------|---------|
| QPS  | 10026.40 | 10625.16 |
| 平均耗时 (ms) | 99.737 | 94.116 |
| P99 耗时 (ms) | 166 | 142 |

> [!NOTE]
> **P99 耗时**：指 99% 的请求都在该时间内完成，仅 1% 的请求比它更慢。相比平均耗时，P99 更能反映尾部延迟（long tail），避免少数极端值被平均值掩盖。例如 P99=244ms 表示 99% 的请求在 244ms 内完成。

## 结论

### 测试结果汇总

| 场景 | 指标 | 直查 DB | 缓存命中 | 提升幅度 |
|------|------|---------|---------|---------|
| 单表查询 | QPS | 8110.24 | 10175.79 | +25.5% |
| 单表查询 | 平均耗时 | 123.301ms | 98.272ms | -20.3% |
| 单表查询 | P99 耗时 | 244ms | 165ms | -32.4% |
| 连接查询 | QPS | 10026.40 | 10625.16 | +6.0% |
| 连接查询 | 平均耗时 | 99.737ms | 94.116ms | -5.6% |
| 连接查询 | P99 耗时 | 166ms | 142ms | -14.5% |

### 分析

1. **缓存对单表查询提升更明显**：单表查询场景下，缓存命中相比直查 DB 提升约 25%（QPS）和 32%（P99），符合预期。

2. **连接查询的直查性能出乎意料地高**：H2 内存数据库的 JOIN 操作效率很高，直查 DB 的 QPS（10026）甚至高于单表查询的直查 QPS（8110），导致缓存的相对收益被缩小。

3. **P99 改善优于平均耗时**：两个场景中 P99 的提升幅度均大于平均耗时，说明缓存不仅降低了整体延迟，还有效抑制了尾部延迟尖刺。

4. **本次实验的局限性**：H2 是内存数据库，DB 查询本身极快，缓存优势被压缩。在真实生产环境（如 MySQL/PostgreSQL 网络 I/O + 磁盘 I/O）中，缓存的收益预计会显著放大。
